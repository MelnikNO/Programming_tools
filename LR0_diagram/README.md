## Решение

Тема ВКР - Разработка информационной системы для фиксации результатов бесед с родителями обучающихся в общеобразовательной школе

Разрабатываемый продукт — приложение **«Фиксация бесед с родителями»**. Система предназначена для учителей, завучей и директора школы. Она позволяет фиксировать, хранить и анализировать результаты индивидуальных и групповых бесед с законными представителями учеников.

**Основные бизнес-процессы:**
* Ведение картотеки обучающихся и их законных представителей (родителей).
* Регистрация фактов индивидуальных и групповых бесед (дата, тема, содержание, результат).
* Назначение и контроль исполнения договорённостей (поручений) по итогам бесед.
* Разграничение прав доступа: педагоги видят только своих учеников, завучи контролируют выполнение задач, администраторы управляют пользователями.

**Подход к выполнению задания и процесс генерации**

В ходе работы были последовательно реализованы следующие этапы:
1. **Анализ требований:** Выделены актёры и сущности, определены границы системы.
2. **Статическое моделирование:** Построены диаграмма вариантов использования (Use Case) для фиксации функционала и диаграмма классов (Classes) для описания структуры данных.
3. **Динамическое моделирование:** Построены диаграммы последовательности (Sequence), состояний (State) и деятельности (Activity), отражающие поведение системы во времени.
4. **Генерация программного кода:** На основе диаграммы классов сгенерирован программный код доменной модели на языке **Python** (с использованием библиотеки `dataclasses`). Код готов к интеграции с ORM (например, SQLAlchemy) для создания базы данных.
5. **Прототипирование:** Создан визуальный макет (wireframe) главного экрана системы.

На диаграмме представлены три актёра. Иерархия прав реализована через наследование: *Завуч* наследует права *Педагога*, а *Администратор* — права *Завуча*. Сценарий «Создать договорённость» является опциональным расширением базового сценария (`<<extend>>`).

Диаграмма демонстрирует клиент-серверную архитектуру. Педагог через интерфейс (UI) отправляет POST-запрос. Контроллер передает данные сервису (бизнес-логике).
